# Интерфейс клиента и банка

React 19 + TypeScript + Vite. Production-интерфейс обслуживает nginx; запросы `/api` проксируются в Spring Boot.

[Демонстрация для проверяющих](../docs/hackathon-start.md) · [Общая документация](../docs/README.md)

## Запуск

Полный проект запускается из корня скриптом `scripts/start-demo.ps1` или `bash scripts/start-demo.sh`. Интерфейс: http://localhost:3000.

Для разработки frontend:

```bash
npm --prefix frontend ci
npm --prefix frontend run dev
```

Vite: http://127.0.0.1:5173; backend по умолчанию http://127.0.0.1:8080. Настройки proxy находятся в [vite.config.ts](vite.config.ts).

## Клиентский процесс

1. Каталог, фильтры и условия продукта.
2. Предварительная форма: 15 полей, пример заполнения, проверка значений.
3. Результаты применимости и E5-ранжирования, сохранённые подборы.
4. Выбор продукта и черновик заявки: 17 полей с переносом 13 общих.
5. Дополнение финансовых сведений, загрузка и замена версий документов.
6. Подтверждение подачи, дозапрос и повторная подача.
7. Просмотр условий, принятие обычного или встречного предложения.
8. Подтверждение демонстрационного договора и просмотр выдачи.

## Кабинет банка

Вход `demo-bank` открывает раздел «Кабинет банка». Доступ определяется серверной ролью `BANK_APPROVER`.

- Пагинированная очередь и назначение заявки.
- Создание действующего макроэкономического контекста.
- Скачивание и проверка текущих версий документов с комментарием.
- Запуск проверок и скоринга, просмотр решения и согласованных условий.
- Ручное решение и дозапрос с причиной.
- Учебная выдача после подписания.

## Сессия и сохранение

Сессия передаётся HttpOnly-cookie; `/me` восстанавливает пользователя при загрузке. Изменяющие запросы используют CSRF-токен. Выход отзывает серверную сессию и синхронизируется между вкладками.

Предварительная форма гостя хранится в текущей вкладке до 24 часов, затем переносится на сервер при входе. Формы после входа и заявки DRAFT/NEEDS_INFO автоматически сохраняются с задержкой 700 мс. UI показывает состояние сохранения. Экран, профиль, подбор и заявка восстанавливаются по валидированным идентификаторам URL. Версии проверяются сервером при записи.

Money вводится в удобном формате, а API получает строки с двумя знаками после точки. Доля просрочки показывается в процентах и передаётся JSON-числом [0,1].

## Проверки

```bash
npm --prefix frontend test
npm --prefix frontend run build
```

Тесты проверяют формы, сериализацию, cookie/CSRF, восстановление экранов и сохранение черновиков. Сборка включает TypeScript и Vite. Проверка полного HTTP-процесса описана в [validation.md](../docs/validation.md).
