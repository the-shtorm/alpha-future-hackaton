# Кабинет финансирования бизнеса

React 19 + TypeScript + Vite. Button/Input/Textarea и CSS-токены подключены из
официальных пакетов [Core Components](https://core-ds.github.io/core-components/master/?path=/docs/intro--docs).
Используется стек AlfaSans с системным fallback; проприетарные файлы шрифтов не включены.
Каталог синтетический и не является реальным банковским предложением.

## Запуск

```sh
npm --prefix frontend ci
npm --prefix frontend run dev
```

Vite: http://127.0.0.1:5173, API по умолчанию http://127.0.0.1:8080.
Если backend на другом адресе, задайте ALPHA_API_TARGET процессу Vite.
Docker: `docker compose up -d --build`, UI http://127.0.0.1:3000 (FRONTEND_PORT).
nginx проксирует /api в backend; сервисные ключи Recsys не попадают в браузер.

В локальном .env для создания demo-owner нужны SPRING_PROFILES_ACTIVE=demo и
DEMO_PASSWORD длиной от 12 символов (до 72 байт UTF-8), затем
`docker compose up -d backend`. Учётная запись создаётся при запуске только при
наличии пароля. Изменение переменной не сбрасывает пароль уже существующего пользователя.
Для старого аккаунта используйте ранее заданный пароль; общедоступного пароля в коде нет.
Секреты и ответы не хранятся в localStorage/sessionStorage. Logout отзывает сессию.

## Пользовательский путь

1. Главный экран — публичный каталог 15 продуктов: категории, поиск, сумма, цель и
   фильтр без имущественного залога. В карточках суммы, сроки, ставка и обеспечение.
2. «Подробнее» открывает условия продукта, требования к бизнесу и комиссии из API.
3. «Выбрать условия» открывает форму из 15 полей Preliminary Form 2.0. Сумма, цель,
   срок и режим использования предзаполнены по продукту; клиент может их изменить.
4. Перед сохранением требуется вход и компания с ролью OWNER/EDITOR.
5. Сервер проверяет применимость и сам вызывает Recsys, если настроен RECSYS_URL.
   При отсутствии сервиса остаются проверенные продукты и честное сообщение о
   недоступности персонального подбора. Сходство не превращается в вероятность,
   технические оценки не показываются клиенту. Все предупреждения сохраняются.
6. «Мои подборы» получает сохранённые профили из backend, файлы JSON не нужны.
7. «Начать оформление» фиксирует выбранную версию и создаёт черновик заявки.
   «Мои заявки» показывает список, финансовые дополнения, исходные ответы, документы
   и историю статусов. Сохранение черновика не отправляет заявку.
8. Отправка требует отдельного подтверждения сведений. Решение и банковские действия
   выполняются существующим backend; банковский интерфейс и реальная выдача не реализованы.

Налоговый режим совместим с формой бизнеса. Деньги отправляются строками с двумя
знаками после точки без арифметики float; неизвестные данные не заменяются нулями.
Поля географии, даты регистрации и специальные счётчики в форме отсутствуют.
Для запроса данных используются только пользовательские endpoint'ы backend.

Перед подбором форма проверяет сумму по диапазонам загруженного каталога, целый
срок 1–360 месяцев и корректность дат. Если указана выручка (включая ноль), нужен
полный период: с первого по последний день месяца. Выручка ниже требований продуктов
даёт пустой подбор с причинами; пустое поле остаётся неизвестным значением.
Выпадающие списки поддерживают стрелки, Home/End, Enter, Escape и поиск набором текста.
Страницы, шаги, карточки, окна и списки имеют короткие анимации появления; при
`prefers-reduced-motion: reduce` движение отключается. Анимации не задерживают действия.

Загрузка документов: PDF/PNG/JPEG до 10 МБ; nginx допускает запрос до 11 МБ с учётом
multipart. Загруженный файл ожидает проверки, загрузка не означает VERIFIED.
