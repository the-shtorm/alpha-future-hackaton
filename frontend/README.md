# Кабинет финансирования: первая версия UI

React 19 + TypeScript + Vite. Button/Input/Textarea и CSS-токены подключены из
официальных отдельных пакетов Core Components: button 13.2.4, input 17.2.2,
textarea 10.1.4 и vars 11.4.1 (набор из версии 50.38.0) по указанной пользователем
[документации Core Components](https://core-ds.github.io/core-components/master/?path=/docs/intro--docs).
Шрифт — стек `--font-family-alfasans`/`--font-family-styrene` библиотеки с системным
fallback: проприетарные файлы шрифтов не добавлены. Общий layout проекта и SVG-иконки
собственные; это хакатонный прототип, не официальный банковский кабинет.

## Запуск

```sh
npm --prefix frontend ci
npm --prefix frontend run dev
```

Открыть http://127.0.0.1:5173. Backend должен работать на 127.0.0.1:8080.
Vite проксирует `/api` к Spring; при другом адресе задайте `ALPHA_API_TARGET` процессу Vite.
В Docker: `docker compose up --build`, UI http://127.0.0.1:3000 (FRONTEND_PORT),
nginx проксирует `/api` к backend. Секретов во frontend environment нет.
Для DEMO-логина профиль Spring `demo`, пароль задаётся `DEMO_PASSWORD` в backend;
пользователей без компаний OWNER/EDITOR форма не допускает к проверке.

## Работа

1. Заполнить бизнес-поля и потребность. «Заполнить пример» использует явно синтетические данные.
2. Войти, выбрать компанию, нажать «Проверить форму».
3. Посмотреть допустимые продукты и предупреждения, отдельно причины исключений.
4. Скачать пакет JSON и передать команде самостоятельно. Можно скачать шаблон ответа:
   `similarityScore: null` — незаполненное место, сервер его не примет как оценку.
5. Загрузить ответ файлом или вставить JSON, применить. Появятся порядок и техническое сходство, выделение первых topK (максимум трёх) и неизменённые условия применимости.
6. Выбрать продукт. UI полной банковской заявки пока не входит в эту первую версию.

При перезагрузке страницы вход и данные в памяти сбрасываются. Для продолжения нажмите
«Продолжить подбор из файла» и загрузите ранее скачанный пакет; приложение получает
актуальный серверный снимок по profileId/requestId, проверяя доступ. После изменения формы
нужна новая проверка. Загруженные локальные поля предупреждений не используются.
Один импорт сохраняется на подбор; полные правила в [контракте обмена](../docs/ranking-exchange.md).
Bearer, пароль и ответы не пишутся в localStorage/sessionStorage; logout отзывает
сессию на сервере. UI отправляет запросы только своему backend, внешние сервисы не вызываются.

```sh
npm --prefix frontend run build
npm --prefix frontend test
```

Production build проверяет TypeScript и собирает dist/. Проверки в браузере и их ограничения
описаны в отчёте задачи; код бизнес-правил проверяется тестами Spring.
