# Передача дообученной E5 через GitHub / Git LFS

Запрос: просмотреть текущее состояние и продолжить подготовку всех необходимых
данных о модели для GitHub. Пользователь подтвердил закрытый репозиторий по прежнему
адресу и повторил запрет на push. Изменения сохраняются только локально; docs/
не редактируется по прежнему указанию пользователя.

## Найденное состояние

На старте ветка fast_api, HEAD 0b6adf8, рабочее дерево чистое. Пользователь уже
добавил готовую модель в Git LFS: один model.safetensors, 470637416 байт,
OID 502f9765a9cebed997794d64dcdc905721d0ca7b0c47a66262f227ea42a63b4c.
Все 10 файлов final/ отслеживаются. Git LFS fsck успешен. Указатель фиксирует
правильные размер и SHA, а точные байты остальных файлов в коммите совпадают с
manifest. Сами веса, их artifact SHA, runtime policy и зависимости не изменялись.

В документации оставались неверные утверждения об отсутствии весов в Git и
FastAPI-заготовке. CI не скачивал LFS и не проверял готовый опубликованный пакет.

## Подготовлено

- fastapi/MODEL_HANDOFF.md: clone/LFS/auth, проверка целостности, CPU/offline запуск,
  Compose, текущий F1-порог, контракт Java, обучение, splits и оговорки качества.
- scripts.verify_model: проверка LFS pointer, полного manifest и identity,
  опциональный настоящий CPU smoke; сетевых загрузок нет.
- scripts.evaluate_active_model: оценка с текущим порогом без повторной калибровки.
- evaluation/diagnostic-15.json: ранее просмотренные 15 синтетических сценариев,
  которые прежде хранились только локально. Метки не менялись.
- README и experiments/README: актуальные инструкции и ссылка на handoff;
  исторический ZIP/F0.5 явно отделён от текущей F1-политики.
- CI model-package: checkout lfs:true, Git LFS fsck, manifest и offline CPU smoke.
  Ручной real-java получает LFS и проверяет обе модели и оба Java acceptance.
  Обычный contracts остаётся быстрым, с fake encoder без скачивания весов.
- Unit-тесты получения пакета: отсутствие весов, нерешённый LFS pointer,
  проверка identity, smoke/no-smoke.

Локальная копия создана из данного репозитория, а не с GitHub: это проверяет
LFS-передачу и целостность пакета, но не доступность LFS object на сервере GitHub.
Репозиторий закрытый: git ls-remote не смог авторизоваться, подключённый GitHub
connector вернул 404. Пользователь подтвердил корректность URL. До авторизации
удалённое наличие объекта не подтверждено. Никакие push, LFS push, публикация
release или изменения удалённого репозитория не выполнялись.

Повторный Docker Linux smoke пытались выполнить, но Docker daemon недоступен
(dockerDesktopLinuxEngine pipe отсутствует). Этот запуск не считается успешным.
GitHub Actions не запускались из этой задачи; изменён только workflow.
Команда проверки clone вначале была вызвана из неверного cwd и не нашла scripts;
запуск из fastapi/ с явным model-path затем успешно выполнил настоящий CPU smoke.

Результаты оценок: локальные work/ml-acceptance/handoff-final90.json и
handoff-diagnostic15.json; pytest JUnit: fastapi/reports/model-handoff-tests.xml.
Чистая локальная копия: work/ml-acceptance/model-handoff-clone/.

Данные оценки синтетические и уже просмотрены, каталог общий; это диагностическое
воспроизведение, не новая независимая финальная проверка. Исходный архив и
исторические отчёты не перезаписывались. Для серверной публикации остаются доступ
к закрытому GitHub и последующий push пользователем после снятия его запрета.
