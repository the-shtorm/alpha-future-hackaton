# Запуск и демонстрация для проверяющих хакатона

Руководство проводит через запуск, подбор кредита, подачу заявки, банковское рассмотрение, принятие предложения, демонстрационное подписание и выдачу.

## 1. Подготовьте компьютер

- Docker Desktop с Linux-контейнерами либо Docker Engine 25+.
- Docker Compose v2.24+ (`docker compose version`).
- Рекомендуется выделить Docker 6 ГБ оперативной памяти, 4 CPU и около 10 ГБ свободного места.
- Доступ к Docker Hub, GHCR, репозиториям Python-пакетов и Hugging Face при первой сборке.

Java, Spring Boot, Node.js, Python и ML-библиотеки подготавливаются внутри Docker. Для ML-сервиса в Compose задана платформа `linux/amd64`.

Откройте терминал в корне полученного репозитория: здесь находятся `compose.yaml`, `.env.example` и `scripts/`.

## 2. Запустите проект

### Windows

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-demo.ps1
```

Параметр `ExecutionPolicy` применяется к этому запуску PowerShell.

### Linux, macOS, WSL

```bash
bash scripts/start-demo.sh
```

Скрипт:

1. Создаёт `.env` из `.env.example`, если файла ещё нет.
2. Заполняет пустые пароли БД, pgAdmin, клиента и банка, а также внутренний API-ключ случайными значениями.
3. Сохраняет ранее заданные значения и дополняет отсутствующие параметры шаблона.
4. Собирает и запускает сервисы командой `docker compose up --build --detach --wait --wait-timeout 2400`.
5. Дожидается готовности ML и интерфейса с backend API.

При первой сборке загружаются зависимости и две модели. E5 и SBA загружаются по закреплённым HF-версиям, проверяются по manifest/SHA-256 и сохраняются в Docker-томе `recsys_model_cache`. Повторные запуски используют сохранённые образы и кэш.

Проверить состояние:

```bash
docker compose ps
```

Дождитесь `healthy` у `fastapi`, `postgres` и `frontend`. Backend и pgAdmin должны быть запущены. Интерфейс доступен по адресу **http://localhost:3000**.

### Те же действия отдельными командами

Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-demo.ps1
docker compose config --quiet
docker compose up --build --detach --wait --wait-timeout 2400
```

Linux/macOS/WSL:

```bash
bash scripts/setup-demo.sh
docker compose config --quiet
docker compose up --build --detach --wait --wait-timeout 2400
```

## 3. Найдите данные входа

Откройте локальный `.env` в текстовом редакторе.

| Роль | Логин | Пароль из `.env` |
|---|---|---|
| Клиент | `demo-owner` | `DEMO_PASSWORD` |
| Сотрудник банка | `demo-bank` | `DEMO_BANK_PASSWORD` |
| Администратор pgAdmin | Значение `PGADMIN_DEFAULT_EMAIL` | `PGADMIN_DEFAULT_PASSWORD` |

Аккаунты создаются backend при первом запуске demo-профиля. Повторный запуск сохраняет существующие аккаунты и данные. Чтобы выбрать собственные пароли до первой инициализации, заполните эти параметры после `setup-demo` и перед `docker compose up`. Пароль аккаунта — от 12 символов до 72 байт UTF-8.

Для параллельной работы клиента и банка используйте обычное окно браузера и отдельное приватное окно. Открывайте в обоих **один и тот же адрес** `http://localhost:3000`.

## 4. Подготовьте учебный макроконтекст банка

1. В приватном окне нажмите «Войти» и используйте `demo-bank`.
2. Откройте «Кабинет банка» → «Макроэкономический контекст».
3. Для демонстрации задайте ставку `10`, источник `DEMO_HACKATHON` и дату окончания через несколько дней от текущей даты.
4. Нажмите «Сохранить контекст».

Это учебное значение для воспроизводимого сценария. Контекст сохраняется с источником, сроком действия и версией.

## 5. Создайте заявку клиента

В обычном окне войдите как `demo-owner`, начните подбор и заполните форму. Для сценария одобрения используйте:

| Поле | Значение |
|---|---|
| Форма бизнеса | ООО |
| Отрасль | Торговля |
| Фактическое начало деятельности | `2020-01-01` |
| Налоговый режим | УСН |
| Реестр МСП | Нет |
| Цель | Оборудование |
| Сумма | `500000` ₽ |
| Срок | `60` месяцев |
| Использование | Разовое получение средств |
| Выручка за период | `24000000` ₽ |
| Период выручки | Последние 12 полных календарных месяцев |
| Готовность предоставить залог | Да |
| Готовность к поручительству | Да |
| Описание | Например, «Покупка оборудования для бизнеса» |

Для даты запуска 26 октября 2026 года полный период — с `2025-10-01` по `2026-09-30`. При другой дате сдвиньте период на последние завершённые месяцы. Кнопка заполнения примера помогает подготовить базовые сведения; затем проверьте значения по таблице.

Получите подбор и выберите продукт **«Оборудование» (P07)**. Сервис проверяет применимость и показывает семантические рекомендации E5. Выбор предложения создаёт черновик полной заявки.

Дополните заявку:

| Поле | Значение |
|---|---|
| Текущие ежемесячные платежи по долгам | `0` ₽ |
| Доля просроченных платежей | `0` % |
| Стоимость предлагаемого залога | `1000000` ₽ |
| Собственное участие | `20` % |

Сведения сохраняются автоматически. Дождитесь сообщения о сохранении перед обновлением страницы.

## 6. Приложите документы и отправьте заявку

1. В разделе «Документы» загрузите файл для каждого показанного требования.
2. Для учебного прогона можно использовать [подготовленный демонстрационный PDF](demo/sample-document.pdf) для каждого требования.
3. Подтвердите сведения анкеты.
4. Нажмите «Отправить заявку».

Принимаются PDF, PNG и JPEG размером до 10 МБ. Загрузка сохраняет версию файла; результат банковской проверки показывается отдельно.

## 7. Проведите банковское рассмотрение

В окне банка:

1. Обновите очередь и откройте новую заявку «Оборудование» (P07).
2. Назначьте заявку себе, если это действие доступно.
3. Для каждого документа заполните «Комментарий к проверке или решению», например `Проверено в учебном сценарии`, и нажмите «Подтвердить документ».
4. Нажмите «Запустить проверки и скоринг».
5. Посмотрите решение, условия и финансовые показатели.

Параметры из раздела 5 используются для воспроизводимого одобрения с рабочей моделью `sba-scoring-v2`. Результат сохраняется вместе с версией анкеты, политики и модели.

## 8. Примите предложение и подпишите

В окне клиента:

1. Откройте заявку и нажмите «Обновить статус».
2. Ознакомьтесь с суммой, сроком, ставкой и сроком действия предложения.
3. Подтвердите принятие и нажмите «Принять предложение».
4. Подтвердите условия демонстрационного договора.
5. Нажмите «Подписать демо-договор».

Сформированный документ доступен в заявке. Подписанные условия используются на этапе учебной выдачи.

## 9. Выполните учебную выдачу

В окне банка обновите заявку:

1. Убедитесь, что статус — `SIGNED`.
2. Подтвердите учебную выдачу.
3. Нажмите «Выполнить демо-выдачу».

Ожидаемый статус — **`DISBURSED`**. В заявке отображается операция с суммой и датой. Обновите окно клиента, чтобы увидеть результат. Процесс демонстрируется на синтетическом каталоге и учебных операциях.

## 10. Дополнительные сценарии

Сохраните общие сведения компании и период из основной таблицы. Документы перед решением подтверждает банк.

| Сценарий | Параметры |
|---|---|
| Встречное предложение | «Экспресс для бизнеса» (P01), оборотные средства, `1000000` ₽, 12 месяцев, выручка `6000000` ₽ за 12 месяцев, текущие платежи `170000` ₽, просрочка 0, залог «Нет», поручительство «Да» |
| Отказ | «Экспресс для бизнеса» (P01), оборотные средства, `300000` ₽, 6 месяцев, выручка `24000000` ₽ за 12 месяцев, текущие платежи 0, просрочка 0 |
| Дозапрос | Оставьте текущие платежи по долгам незаполненными; банк запустит проверку и вернёт заявку на уточнение |

При встречном предложении клиент видит альтернативные условия и выбирает «Принять условия». При дозапросе клиент дополняет заявку и отправляет новую ревизию; банк повторяет проверку. История предыдущих подач сохраняется.

Для замены файла в редактируемой заявке выберите текущую версию в поле «Файл для замены» и загрузите исправленный файл. Список сохраняет историю версий.

## 11. Адреса и состояние сервисов

| Назначение | Адрес |
|---|---|
| Интерфейс | http://localhost:3000 |
| Health через nginx и backend | http://localhost:3000/api/health |
| Backend | http://localhost:8080/health |
| Swagger UI | http://localhost:8080/swagger-ui/index.html |
| OpenAPI | http://localhost:8080/v3/api-docs |
| pgAdmin | http://localhost:5050 |

Обычный ответ health: `{"status":"ok"}`. Состояние загрузки ML видно в логах:

```bash
docker compose logs --tail=100 fastapi
docker compose logs --tail=100 backend
docker compose logs --tail=100 frontend
```

Проверка E5 и SBA внутри работающего контейнера:

```bash
docker compose exec -T fastapi python -m scripts.verify_model --smoke
docker compose exec -T fastapi python -m scripts.prepare_scoring_model --smoke
```

## 12. Остановка и повторный запуск

```bash
docker compose down
docker compose up --detach --wait --wait-timeout 2400
```

`down` сохраняет базу, документы и кэш моделей в томах. Для новой учебной базы используйте отдельное имя проекта и свободные порты — [конфигурация](configuration.md). Команда `docker compose down --volumes` удаляет данные и кэш именно выбранного Compose-проекта; выполняйте её только при намеренном полном сбросе демонстрации.
