# Дообучение скоринга: recall ≥90%, precision ≥60%

**Статус: предложение, новые модели ещё не обучались.** Реализован и проверен
выбор порога под оба ограничения. Вся сетка требует нового training runner.
Текущий пакет и runtime не изменены.

## Цель и оптимальная комбинация

Для каждого обученного варианта `m` ищем собственный порог:

`t*(m) = argmax F1(m,t)` при `recall(m,t) ≥0.90` **и** `precision(m,t) ≥0.60`.

Оба условия выполняются при **одном пороге на одной когорте**. При равном F1
предпочитаем больший recall, затем precision. Граничные precision=0.60 и recall=0.90
дают F1=0.72; это критерий, а не обещание результата.

Для каждого реального обучения перебираем все уникальные вероятности и границы
0/1 с правилом `p >= t`. Одинаковые скоры не разделяются. Ни фиксированного 0.5,
ни среднего по порогам. Precision, F1 и recall всегда принадлежат одной точке.

Если допустимых порогов нет: `status=infeasible`, `optimal=null`. Показываем
отдельные полные точки: максимум recall при precision ≥60%, максимум precision
при recall ≥90%, максимум F1 без ограничений. Они не объявляются достижением цели.
Отдельные выборки обучения и выбора порога согласуются с
[рекомендациями scikit-learn](https://scikit-learn.org/stable/modules/classification_threshold.html).

## Исходная модель: цель пока недостижима порогом

На 41 892 порогах FY2017 нет точки, выполняющей оба ограничения:

| Оптимум на FY2017 | Порог | Precision | F1 | Recall |
|---|---:|---:|---:|---:|
| Максимум recall при precision ≥60% | 0.210646847923 | 60,0035% | 0.710630 | 87,1204% |
| Максимум precision при recall ≥90% | 0.152837075378 | 55,7961% | 0.688874 | 90,0051% |

Это точки существующей модели на когорте калибровки, **не дообучение и не независимый
тест**. [Baseline с хешами](../fastapi/experiments/sba-scoring-retraining-plan-v1/current-model-business-targets.json).
Сильное ухудшение переноса по времени из предыдущего эксперимента делает актуальность
данных более приоритетной гипотезой, чем простое повышение веса списаний.

## 1. Аудит данных перед сеткой

В CSV только завершённые кредиты. Все записи имеют snapshot **2026-06-30**;
FY2025 содержит 82 списания, FY2026 — ноль. Это не доказывает низкий риск всех
недавних выдач. Есть девять входных признаков и даты выдачи/исхода.

| Проверка / гипотеза | Действие |
|---|---|
| Изменяемый `TermInMonths` | Подтвердить договорный срок на момент заявки; обязательно сравнить модель без срока. Ветка со сроком исследовательская до подтверждения. |
| Зрелость меток | Изучить время от выдачи до snapshot и исхода по классам/годам; отсутствие исхода не считать погашением. |
| Доступность исхода во времени | При историческом обучении учитывать только метки, известные к соответствующему deadline. |
| Завершённые кредиты | Для устранения selection bias получить полный портфель, включая активные; одним фильтром дат проблему не исправить. |
| Категориальный drift | Проверить изменение смысла и долей BusinessAge/BusinessType/NAICS, появление новых и редких категорий. |
| Реальная область backend | Показывать полную когорту и backend-достижимые категории; не подменять весь поток удобным подмножеством. |
| Дубликаты | Проверить повторы и противоречия. Совпадение девяти полей не доказывает одного заёмщика; не удалять автоматически. |
| Качество значений | Проверить USD, процентные пункты, коды, выбросы и порядок дат; исправления версионировать. |
| Горизонт | «Когда-либо списан» и «за 12/24/36 месяцев» — разные цели. Для горизонта нужны полноценное наблюдение и цензурирование; новая цель получает версию. |

Даты погашения/списания, snapshot и индекс строки в X не входят. Survival-модели
имеют смысл после получения активных/цензурированных кредитов; текущая выборка
только завершённых кредитов сама по себе для исправления этого смещения недостаточна.

## 2. Основная сетка: 480 обучений

Стартовая модель: CatBoost depth=6, lr=0.06, l2=10, до 3000 деревьев,
early stopping=150, seed=42, CPU/4 потока. Это предлагаемые стартовые значения.
Число деревьев выбирать по невзвешенной `PRAUC:type=Classic;use_weights=False`;
финальный критерий — точка с двумя ограничениями. PRAUC — вспомогательный показатель,
не замена трём требуемым метрикам. [Метрики CatBoost](https://catboost.ai/docs/en/concepts/loss-functions-classification).

| Ось | Варианты | Число |
|---|---|---:|
| Окно до исторической границы | Вся история; последние 10, 7, 5, 3 года | 5 |
| Давность | Без убывания; полураспад 1, 3, 5 лет | 4 |
| Вес списаний | 1; 1.5; 2; 3; 5; 8; SqrtBalanced; Balanced | 8 |
| Признаки | Исходные 9 для диагностики; безопасные 8 без срока; обогащённые безопасные 8 | 3 |
| **Итого** | **Каждый fit → собственный полный перебор порогов** | **480** |

Вес давности: `2 ** (-age_years / half_life_years)`, возраст до обучающей границы,
не до будущего snapshot. Sample weights нормализовать, class weighting записывать
отдельно. Не совмещать explicit class_weights, auto_class_weights и scale_pos_weight:
они взаимоисключающие. [Параметры CatBoost](https://catboost.ai/docs/en/references/training-parameters/common).
Validation/threshold/evaluation сохраняют естественные доли классов; пользовательские
precision/F1/recall считаются невзвешенно, без ресэмплирования оценки.

## 3. Максимальный набор гипотез для признаков

Ожидаемый эффект — гипотеза. Все статистики и преобразования fit только на train.

| Группа | Что сравнить | Условие |
|---|---|---|
| Сумма | Исходная, log1p, интервалы квантилей, индикаторы крайних значений | Границы train-only. |
| Ставка | Исходная, интервалы, ставка×F/V, ставка×тип бизнеса | Значения доступны до выдачи. |
| NAICS | Полный код, префиксы 2/3/4, полная иерархия одновременно | Строковые категории. |
| Частоты | Частота отрасли и сочетаний, unknown/rare indicators | Только прошлые данные. |
| Редкие категории | Объединение при числе <20/50/100/300, сглаживание | Словарь из train. |
| Возраст бизнеса | Исходные категории, проверенные укрупнения | Не считать коды линейной числовой шкалой. |
| Взаимодействия категорий | Отрасль×возраст, тип×возраст, collateral×revolver, отрасль×тип | Контроль разреженности. |
| Число×категория | Сумма×collateral/revolver, ставка×тип | Сравнить с неявными взаимодействиями деревьев. |
| Исторические агрегаты | Отклонение суммы/ставки от медианы отрасли/сегмента | Сглаживание и train-only fit. |
| Target encoding | Сглаженный исторический риск категорий | Только хронологический OOF, сравнить с native CatBoost. |
| Срок и производные | Срок, интервалы, сумма/срок, расчётный аннуитет | Только после проверки исходного срока; это не доход и не DSCR. |
| Дата заявки | Год/календарный режим как доступный контекст | Проверить экстраполяцию; сейчас вне API. |
| Макроэкономика | Доступные на дату выдачи ставки, инфляция, отраслевой цикл | Нужны внешние ряды без будущих пересмотров. |
| Финансовое состояние | Выручка, cash flow, долговая нагрузка, покрытие платежей, маржа | Нужны размеченные кредиты с этими полями; наличия полей в backend недостаточно. |
| Кредитная история | Предшествующие просрочки, текущий долг, история погашений | Нужны соответствующие исторические данные и исходы. |
| Абляции | Исключать по одному признаку и группами | Новый порог для каждой абляции. |

`engineered_safe8` первой волны: сумма/ставка, NAICS-иерархия, частоты, редкость и
взаимодействия без срока и его производных. Остальные варианты — отдельные расширения.

## 4. Уточнение CatBoost: до 360 новых fits

До 12 отобранных конфигураций ×30 условных проб. Это не полное произведение
огромного пространства; каждый реально обученный вариант получает свой threshold search.

| Параметр | Предлагаемые значения |
|---|---|
| depth | 4, 5, 6, 7, 8, 10 |
| learning_rate | 0.015, 0.03, 0.06, 0.10 |
| l2_leaf_reg | 1, 3, 10, 30, 100 |
| random_strength | 0, 0.5, 1, 2, 5 |
| rsm / border_count | 0.6/0.8/1; 64/128/254 |
| Bootstrap | Bayesian temperature 0/0.5/1/3; Bernoulli/MVS subsample 0.6/0.8/1 |
| Boosting / деревья | Plain/Ordered; SymmetricTree/Depthwise/Lossguide |
| min_data_in_leaf | 20/100/500 только для Depthwise/Lossguide |
| max_leaves | 16/32/64 только для Lossguide |
| Порядок | has_time=False/True; True только с сортировкой по реальной дате выдачи |
| Дополнительные абляции финалистов | one_hot_max_size, сложность и сглаживание CTR |

Проверять совместимость параметров с установленной версией. Поддержку и ограничения
описывает [CatBoost tuning](https://catboost.ai/docs/en/concepts/parameter-tuning).
Logloss остаётся обучающей функцией; precision/recall/F1 не подставляются как
дифференцируемый loss. Бизнес-цель — внешний выбор конфигурации и порога.

## 5. Другие эвристики обучения

| Эвристика | Варианты | Условие |
|---|---|---|
| Обучение заново | Актуальные окна и регуляризация | Основная ветка при drift. |
| Warm-start | init_model; +100/300 деревьев; lr 0.01/0.03/0.06; окно 3/5 лет; replay старых данных 25/50%: 24 варианта | CPU; совместимые входы; checkpoint до cutoff. Старые деревья сохраняются. |
| Hard positives | OOF-пропущенные списания с повышенным весом | Ошибки только из train-OOF. |
| Hard negatives | OOF-погашенные кредиты с высоким риском с повышенным весом | Для роста precision, проверять recall. |
| Веса сложных случаев | Отдельно FN/FP ×1.5/2/3 с ограничением итогового веса | Не перемножать агрессивные схемы вслепую. |
| Undersampling | Все списания + погашенные; отношения 1:3/1:5/1:10 | Только train; равноправный baseline без sampling. |
| Oversampling | Повторение редкого класса | Не переносить копии через границы. |
| SMOTENC | Низкоприоритетная абляция для смешанных типов | Реалистичность категорий, train-only fit; обычный SMOTE не подходит. |
| Веса домена | Ограниченные веса целевых сегментов | Оценивать из доступного исторического потока. |
| Сегментные эксперты | Крупные отрасли/типы + общая fallback-модель | Минимальный support, итог по всей когорте. |
| Две ступени | Первый этап с высоким recall, второй снижает FP | Метрики по всей исходной когорте; потерянные на первом этапе списания не восстановятся. |
| Focal/custom loss | Последующая исследовательская ветка | Проверка реализации/градиентов; вне основного бюджета. |

См. [CatBoost init_model](https://catboost.ai/docs/en/concepts/python-reference_catboostclassifier_fit)
и [SMOTENC](https://imbalanced-learn.org/stable/over_sampling.html). Ветка safe8
не может продолжить checkpoint original9. Warm-start сравнивается с переобучением
с нуля; изначальная модель не должна содержать данные будущего исторического fold.

## 6. Другие семейства и ансамбли

До **168** дополнительных обучений с лучшими безопасными представлениями:

- **LightGBM, 60 проб:** листья 15/31/63, leaf support 50/200/500, регуляризация,
  feature/bagging fractions, веса классов. is_unbalance и scale_pos_weight не
  совмещаются. [Параметры](https://lightgbm.readthedocs.io/en/stable/Parameters.html).
- **XGBoost, 60 проб:** depth 3/5/7, min_child_weight, L1/L2, row/column sampling,
  scale_pos_weight, max_delta_step 0/1/5. [Параметры](https://xgboost.readthedocs.io/en/stable/parameter.html).
- **LogisticRegression, 24:** C 0.01/0.1/1/10 ×вес 1/3/8 ×два безопасных feature bundle.
- **RandomForest, 24:** depth 6/12/без лимита ×лист 10/50 ×max_features 0.7/1 ×
  class_weight none/balanced_subsample; 500 деревьев как стартовая гипотеза.
- **Blending:** до пяти пар ×веса 0.1/0.25/0.5/0.75/0.9 =25 комбинаций предсказаний.
- **Stacking:** последующее расширение с хронологическими OOF-предсказаниями.

У каждого ансамбля собственный порог. Усреднять вероятности для построения ансамбля
можно; его precision/F1/recall вычисляются заново, не усредняются из участников.
Новые семейства требуют зависимостей и serving-адаптера, сейчас не реализованы.

## 7. Калибровка

Сравнить отсутствие калибровки, sigmoid и isotonic у финалистов. Калибратор fit
отдельно от модели и порога, на естественной доле классов. Строго возрастающая
sigmoid сохраняет ranking: при полном переборе она не создаст отсутствующую точку
precision/recall на том же наборе. Isotonic может объединять скоры в одинаковые
значения. Поэтому одна калибровка не обещает нужного улучшения разделимости.
[Документация scikit-learn](https://scikit-learn.org/stable/modules/calibration).
После изменения калибратора порог выбирается заново.

## 8. Временная проверка

Пять ролей: fit → early stopping → calibration → threshold selection → validation
для выбора модели. Последняя роль не называется независимым final test.

| Fold | Fit до FY | Early stop | Calibration | Threshold | Validation |
|---|---:|---:|---:|---:|---:|
| A | 2015 | 2016 | 2017 | 2018 | 2019 |
| B, главная сетка | 2017 | 2018 | 2019 | 2020 | 2021 |
| C | 2019 | 2020 | 2021 | 2022 | 2023 |

Это периоды выдач, а не доказательство доступности меток. На каждом шаге учитывать
дату известного исхода до его deadline; показывать исключённые строки и изменение
состава. Ранняя выдача не разрешает использовать исход, произошедший после
моделируемого обучения. Смещение выборки завершённых кредитов остаётся.

Финалисты: до 10 ×3 seeds (42/137/2026) ×3 folds =90 fits. Для каждого trial/fold/seed
отдельные порог и строка метрик. Показывать все строки и число выполнений ограничений;
не среднее метрик или порогов. Не выбирать удачный seed по финальному тесту.

Порог фиксируется до чтения validation-меток для его оценки. Выбор модели на
validation — разработка. При провале любого ограничения на validation явно
`validationTargetPassed=false`, без подбора нового порога по этим же меткам.

FY2018–2026 уже изучались. FY2024–2026 можно использовать как объявленную заранее
диагностику с учётом незрелости, но новая независимая проверка требует другого
неиспользованного и достаточно наблюдаемого потока. После выбора финалиста —
отдельный последний development-период для нового калибратора и порога, затем заморозка.

## 9. Отчёт каждого реального обучения

`trial | window | features | weights | seed | fold | t* | precision | F1 | recall | TP | FP | FN | rows | status`

Отдельные строки `selection` и `validation` при одном фиксированном t*. Если t*
не существует — infeasible и полные строки ближайших альтернатив. Дополнительно:
время, деревья, хеши, число порогов, доля флагов, годовые/backend-срезы. Не подменять
точку macro/weighted average, PR-AUC или средним по folds. Интервалы неопределённости
дополняют точку; на малых сегментах обязательно показывать количество списаний.

## 10. Порядок и бюджет

1. Аудит дат/срока/зрелости; новый temporal manifest.
2. 480 комбинаций основной сетки на fold B.
3. До 360 уточнений 12 конфигураций.
4. 90 проверок финалистов по folds/seeds.
5. 24 warm-start и 168 альтернативных моделей.
6. До 25 ансамблей предсказаний; каждый с новым полным перебором порогов.
7. Финалист, новый калибратор/порог и новая независимая проверка.

Верхний базовый бюджет — **1 122 fits** до исключения несовместимых/дублирующихся
конфигураций. Калибраторы, дополнительные custom loss и stacking вне этого числа.
Стоимость сначала измеряется пилотом; время и достижение цели пока неизвестны.

[Машиночитаемая матрица](../fastapi/scoring_training/config/recall90-precision60-plan.json).
[Реализованный селектор](../fastapi/scoring_training/business_thresholds.py):
