# Архитектура и кредитный процесс

[Индекс документации](README.md) · [Запуск демонстрации](hackathon-start.md)

## Компоненты

| Компонент | Ответственность |
|---|---|
| React / TypeScript | Каталог, формы, кабинет клиента и кабинет банка |
| nginx | Статический frontend и same-origin `/api` proxy |
| Spring Boot / Java 21 | Доступ, каталог, применимость, хранение, финансовая политика, workflow |
| PostgreSQL 17 / Flyway | Данные, миграции, версии, инварианты и аудит |
| FastAPI / Python 3.11 | Ранжирование E5 и native скоринг CatBoost |
| Том документов | Содержимое файлов с SHA-256 и контролем доступа через backend |

## Два связанных процесса

```text
Каталог → preliminary-2.0 (15 полей) → eligibility → E5 → выбор версии продукта
                                ↓ 13 общих полей
application-3.0 (17 полей) → документы → подача неизменяемой ревизии
→ банковские проверки → SBA + финансовая policy → решение
→ акцепт предложения → демонстрационный договор → учебная выдача
```

`request.usageMode` и `request.description` остаются в контексте предварительного подбора. В полную заявку добавляются текущие платежи, доля просрочки, стоимость залога и собственное участие.

## Роли

`OWNER` подтверждает подачу, акцепт и подписание; `EDITOR` редактирует доступные черновики; `VIEWER` читает доступные данные. `BANK_APPROVER` работает с очередью, проверками, решением, макроконтекстом и выдачей. Членство в компании и банковская роль проверяются сервером.

## Состояния заявки

```text
DRAFT → SUBMITTED → VALIDATING → ENRICHING → SCORING
                                    → UNDER_REVIEW
                                    → APPROVED → OFFER_ACCEPTED
                                    → COUNTEROFFERED → OFFER_ACCEPTED
                                    → DECLINED
                                    → NEEDS_INFO → новая подача
OFFER_ACCEPTED → SIGNED → READY_FOR_DISBURSEMENT → DISBURSED
```

Банковская команда запускает обработку поданной ревизии. Положительное ручное решение подтверждает результат действующей policy и проверок. Дозапрос содержит причину и недостающие сведения.

## Рекомендации и риск

E5 сортирует подходящие версии продуктов по смыслу шести query-полей. Серверная применимость и условия сохраняются при обмене. Полный список кандидатов и признак рекомендации сохраняются в подборе.

CatBoost `sba-scoring-v2` возвращает вероятность списания, балл и метаданные. Java применяет `data-policy-3.0-sba-annuity-1`: аннуитет, платежи, выручку, просрочку, правила обеспечения и условия продукта. Альтернативные условия оцениваются повторно. Исторические ревизии выбирают сохранённую версию policy.

## Данные и аудит

- Оптимистические версии защищают редактирование форм и заявок.
- Выбор привязан к версии формы, runId и версии продукта.
- Каждая подача создаёт снимок с SHA-256 и перечнем версий документов.
- Idempotency-Key связывает повтор подачи с прежней ревизией.
- Замена документа создаёт новую версию с сохранением истории.
- ML-входы и выходы записываются в assessment_run; решение связано с выбранной оценкой.
- Встречное предложение хранится отдельно, акцептуется по UUID и SHA-256 условий.
