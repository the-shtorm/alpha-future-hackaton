# Реализация Data Policy 2.1 / Preliminary Form 1.1

Ветка backend-tasks_v2. Источники: [Data Policy](data-policy.md),
[предварительная форма](preliminary_form.md). Отдельный отчет:
[2026-10-23-data-policy-2-1.md](agents/backend/2026-10-23-data-policy-2-1.md).

| Этап | Реализация |
|---|---|
| Предварительная форма | 21 поле, частичное сохранение, проверка типов, версия и optimistic locking |
| Каталог | 15 синтетических продуктов, версии условий, ограничения и описание полей/встречных изменений |
| Eligibility | Все ограничения предварительной формы, PASS/FAIL/UNKNOWN/REVIEW и причины |
| Результат подбора | Неизменяемый снимок только формы, порядок применимость→код; персонального рейтинга нет |
| Выбор | runId + версия формы + productVersionId; изменение формы сбрасывает выбор |
| Заявка | Создается из выбранного профиля; 11 полей переносятся, еще 4 заполняются отдельно |
| Контекст | Восемь полей подбора отдельно от 15 полей answers; обновление контекста явной командой в DRAFT/NEEDS_INFO |
| Проверки | Обязательные сведения, документы, обеспечение, бюджет и ограничения продукта |
| Операции | Отдельное доказательство выручки, исключение переводов/кредитов, ручная проверка расхождений |
| Макроконтекст | Добавляемые версии ставки с источником и сроком; без автоматического подключения ЦБ |
| Оценка | Явно разрешенная пользователем фиксированная взвешенная DEMO-сумма, не модель |
| Решения | APPROVED / COUNTEROFFERED / DECLINED / REQUEST_INFO; ручная проверка — состояние UNDER_REVIEW |
| Встречное предложение | Снижение суммы, повышение ставки key+margin, точный бюджет, новая DEMO-оценка кандидата |
| Акцепт | Подтверждение сохраненной альтернативы по UUID/hash; Offer создается атомарно после акцепта |
| Завершение | Предложение, условный договор и одна демо-выдача |
| Демонстрация | 8 компаний/сценариев, доступных участникам через /demo/scenarios |

Предварительное INELIGIBLE не является банковским DECLINED. Рейтинг рекомендации не
является вероятностью одобрения; персональное ранжирование не имитируется.
Классификация размера бизнеса не выводится из boolean mspRegistry.
При отсутствии обязательной оценки или макроконтекста нет автоматического одобрения.
Ручная банковская команда не может обойти жесткий отказ, документы и оценку.

Не добавлены обученная модель, ее загрузчик, ML-клиент/контракт, вызовы FastAPI,
LLM-ассистент и персональный recsys: это ответственность другой команды/отдельных задач.
Для неаннуитетных графиков потребуется согласованный расчет; сейчас REQUEST_INFO.
Изменение срока или другого продукта не выдается за разрешенную альтернативу текущего продукта.
Другой продукт выбирается через новый подбор и отдельную заявку.

История V1–V7 сохранена. Новые миграции V8–V9 добавляют данные без удаления существующих.
После каждой задачи создается новый файл отчета; log.md содержит только индекс.


Новый сценарий ручного обмена и форма 1.1: [Query/Passage MVP — реализация](ranking-exchange.md).
