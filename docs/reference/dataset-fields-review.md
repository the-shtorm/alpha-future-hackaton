# Справочник полей SBA 7(a) для бэкенда кредитного MVP

Версия документа: 1.0. Дата: 24 октября 2026 года.

## 1. Назначение и границы

Документ описывает **каждое из 42 полей** `FOIA_7a_FY2010_FY2019_asof_260630.csv`: название и смысл, тип после импорта, качество данных и применение в нашем проекте. Он предназначен для разработчиков Spring Boot, FastAPI и подготовки ML-данных.

Основание: исходная спецификация `scoring_dataset_requirements.md`, выполненный технический аудит всего CSV и [официальный словарь SBA](https://data.sba.gov/sites/default/files/uploaded_resources/7a_504_foia_data_dictionary.xlsx). [Страница источника](https://data.sba.gov/dataset/7a-504-foia).

В источнике **545 751 строка**, срез **30.06.2026**, одобрения **01.10.2009–30.09.2019**. Для CHGOFF/PIF до очистки доступно **428 874 строки**, из них **34 153 CHGOFF**. Все приведённые фактические диапазоны и пропуски относятся именно к этой версии. Это не обязательные продуктовые лимиты и не гарантия допустимости значений будущих заявок.

**Архитектурный контекст:** Spring Boot хранит профиль бизнеса и заявки, управляет каталогом и кредитной политикой. FastAPI готовит согласованные признаки и вызывает выбранную модель. Модель оценивает неблагоприятный исход для бизнеса и конкретных условий сделки. Рекомендации продуктов и окончательное одобрение — отдельные задачи.

**Рабочий таргет:** списание CHGOFF против полного погашения PIF среди кредитов с раскрытым исходом. Это не вероятность одобрения, не просрочка 90+ за 12 месяцев и не подтверждённая вероятность дефолта российского бизнеса.

## 2. Как читать типы и роли

CSV физически хранит текстовые ячейки, в том числе числа вида `120.0`. Ниже указан **логический тип после разбора** и рекомендуемые прикладные типы. Конкретная реализация DTO/БД пока не создана; имена прикладных полей и правила контракта являются предложением.

- Даты без времени: `LocalDate` / `date` / SQL `DATE`. Не придумывать часовой пояс и время суток.
- Денежные суммы: `BigDecimal` / `Decimal` / SQL `NUMERIC`. Точность и scale согласовать в схеме. Не терять точность через Double в финансовых расчётах.
- Коды и идентификаторы: строки, даже если состоят только из цифр. Сохранять ведущие нули.
- Y/N: преобразовывать явным словарём. В Java для неизвестного использовать `Boolean`, а не примитивный `boolean`, либо enum с UNKNOWN.
- Пустая ячейка: `null`. Не заменять неизвестное нулём, false или «хорошим исходом».
- Даты исходов и посткредитные события: хранятся для offline-анализа, но отсутствуют в списке входов модели заявки.
- «Кандидат в признаки» не означает окончательный допуск: нужно подтвердить соответствие моменту оценки, воспроизводимость в приложении и качество на отложенных данных.

Для каждого поля ниже указаны формальные пропуски во всём файле и среди CHGOFF/PIF. Пустая дата события может быть структурной. У BusinessAge отдельно учитывается смысловой пропуск Unanswered.

### 01. `AsOfDate` — Дата среза выгрузки

- **Тип данных:** Дата; Java `LocalDate`; Python `date`; SQL `DATE`.
- **Что означает:** Дата, на которую сформирован снимок кредитных данных. Это не дата заявки, одобрения или последнего изменения конкретного кредита.
- **Для чего нужно в проекте:** Метаданные датасета и контроль времени. Не вход модели.
- **Применение в бэкенде:** Хранить в метаданных импортированной версии датасета и протоколе обучения. Не запрашивать у клиента. Использовать для проверки дат исхода и описания версии обучающих данных.
- **Заполненность:** пустых **0 / 0.0000%** во всём файле; **0 / 0.0000%** среди CHGOFF/PIF.
- **Правила и ограничения:** ISO `YYYY-MM-DD`. Весь файл: `2026-06-30`. Найдены 9 ChargeOffDate позже этой даты: пометить и вынести из строгой выборки с исходами на дату среза. Не заменять AsOfDate сегодняшним числом.

## 5. Что именно передавать между Spring Boot и FastAPI

**Не отправлять все 42 поля CSV в модель.** Схема источника, профиль приложения, обучающая строка и запрос inference — разные контракты. Модель ещё не обучена, поэтому ниже приведён предлагаемый состав, а не действующая спецификация API.

| Поле источника | Предлагаемое имя в запросе | Откуда берётся в приложении | Решение для MVP |
| --- | --- | --- | --- |
| GrossApproval | loanAmountUsd | Сумма оцениваемого предложения | Основной кандидат |
| NaicsCode | naicsCode | Согласованный отраслевой справочник профиля | Основной кандидат; ОКВЭД не подставлять напрямую |
| BusinessType | businessType | Профиль и документированное сопоставление категорий | Основной кандидат |
| BusinessAge | businessAgeCategory | Профиль/анкета и правила возрастной категории | Основной кандидат с UNKNOWN |
| RevolverStatus | isRevolving | Условия выбранного продукта | Основной кандидат |
| CollateralInd | hasCollateral | Условия и обеспечение заявки на момент оценки | Основной кандидат при подтверждённой доступности |
| TermInMonths | termMonths | Предложенный договорный срок | Условно; сначала подтвердить семантику источника |
| InitialInterestRate | initialInterestRatePct | Первоначальная ставка предложения | Дополнительно при допуске в модель |
| FixedorVariableInterestInd | interestRateType | Условия предложения | Дополнительно |
| JobsSupported | jobsSupported | Отдельная оценка создаваемых/сохраняемых мест | Дополнительно; не employeeCount |
| ProcessingMethod | sbaProcessingMethod | Сопоставление продукта с программой SBA | Только при осмысленном соответствии; иначе исключить |
| SBAGuaranteedApproval | sbaGuaranteedAmountUsd | Условия гарантии SBA | Для SBA-эксперимента; вне базового российского контракта |

Имена выше нужно один раз зафиксировать в версии feature schema и использовать одинаково в offline-подготовке и inference. Короткий базовый набор — кандидаты, а не обещание достаточного качества без проверки.

Прикладные метаданные запроса могут включать `requestId`, `applicationId`, `productId`, `featureSchemaVersion` и момент оценки. Это **поля нашего приложения, отсутствующие в CSV**; они нужны для маршрутизации, воспроизводимости и хранения, но не становятся предикторами автоматически. Не пытаться получить их из LocationID или имени бизнеса.

Сумму удобно передавать в JSON десятичной строкой, например `"125000.00"`, если этот формат поддержан обоими DTO. Можно выбрать и иной согласованный формат с точным разбором; нельзя смешивать два формата или терять точность на промежуточном шаге. Для ставки явно закрепить: `6.0` = 6%. Для месяцев — положительное целое. Для неизвестной категории — UNKNOWN либо null согласно выбранной схеме и препроцессору. Nullable-вход не означает, что модель обязана принять заявку с любым количеством неизвестных данных.

Spring Boot проверяет применимость продукта и условия предложения, затем передаёт снимок признаков. FastAPI валидирует версию, типы, категории, достаточность данных и преобразует признаки точно так же, как при обучении. Диапазон наблюдений в CSV использовать как сигнал выхода за область обучения, а не автоматически как единственное правило отказа. Как обрабатывать выход за область и недостаточность данных — отдельная политика API.

Скоринговый ответ должен содержать вероятность положительного класса `p`, статус достаточности данных, версию модели/схемы и ограничения. При необходимости `score = 100 × (1 − p)` — только другая шкала того же результата. Решение «одобрить/отказать/уточнить/предложить другие условия» принимает Spring Boot. При встречном предложении передавать новый снимок условий; изменение прогноза не доказывает причинного уменьшения реального риска.

## 6. Разделение хранения и подготовки

Рекомендуемые логические слои, без требования создавать отдельный микросервис или таблицу под каждый:

1. **Сырой импорт:** все 42 исходных поля, исходный файл/версия, хеш файла и номер строки. Не менять исходные данные догадками. Локальный номер строки помогает найти запись, но не является устойчивым ID кредита между версиями.
2. **Нормализованные данные:** даты/числа/коды после разбора, исходные значения рядом при неоднозначности, флаги качества и приближённая группа бизнеса. Ведущие нули идентификаторов сохраняются.
3. **Обучающая выборка:** разрешённые признаки, target, временные части и отдельные метаданные проверки. Служебные колонки и target не входят в feature vector.
4. **Профиль/заявка приложения:** реальные businessId/applicationId, данные пользователя, продукт и версия его условий. Поля SBA не определяют автоматически схему всей бизнес-БД.
5. **Снимок скоринга:** фактически использованные входы, версии препроцессора/модели, время оценки и результат. Для повторного расчёта важен снимок условий, а не только ссылка на изменяемый каталог.

Имена, адреса и точные совпадения использовать только для приближённой группировки и контроля пересечений. В наборе нет доказанного ключа borrower/loan. Поэтому нельзя объявлять все повторы дублями или гарантировать полное отсутствие пересечений бизнеса между train и test.

## 7. Правила, которые следует закрепить до реализации обучения

- **Явный список признаков:** никакого автоматического «все столбцы кроме LoanStatus». Исключить даты/суммы исхода, признаки их заполненности, выдачу после решения и вторичный рынок. Текущие реквизиты кредитора не считать историческими.
- **Время доступности:** определить момент оценки каждого входа. Данные об одобренных условиях подходят для оценки заданного предложения, но не всегда для ранней формы клиента.
- **Target:** использовать только CHGOFF/PIF. EXEMPT не считать отрицательным классом. Не обучать модель отказа в выдаче по данным об исходах уже одобренных кредитов.
- **Срок:** до подтверждения исторического смысла TermInMonths не считать его безопасным признаком. Сопоставить эксперимент с ним и без него, если решено допустить.
- **Преобразования:** правила пропусков, кодирования, агрегации NAICS и масштаба чисел обучать/фиксировать по train и сохранять вместе с моделью. Не вычислять статистики исходов на полном файле.
- **Проверка во времени:** разбиение по ApprovalFY/ApprovalDate дополнить датами доступности исходов и контролем повторных бизнесов. Метка старого кредита могла стать известна позже начала тестового периода.
- **Финансы:** в CSV нет выручки, DSCR, прибыли, транзакций, остатков и истории просрочек. Эти данные можно хранить/проверять в приложении отдельно, но нельзя заявлять, что данная модель их учитывает.
- **Перенос:** явно согласовать USD, отраслевые категории и формы бизнеса. Не подавать рубли, ОКВЭД и российские организационные категории вместо исходных полей без обоснованного преобразования и проверки.
