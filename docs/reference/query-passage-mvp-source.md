# Query и passage для рекомендательной системы — MVP

## 1. Назначение

Документ фиксирует предлагаемый контракт текстового ранжирования для локальной `intfloat/multilingual-e5-small`.

- `query` — описание потребности пользователя, собранное из формы.
- `passage` — описание назначения и особенностей кредитного продукта, собранное из каталога.
- Spring Boot проверяет ограничения и передаёт список допустимых продуктов.
- FastAPI собирает тексты по шаблонам, рассчитывает эмбеддинги и ранжирует переданные продукты.
- LLM для сборки текстов не требуется.

Названия новых полей — предложение для согласования, а не описание уже реализованного API. Схема query опирается на `Main_info/preliminary_form.md` и обсуждённые дополнения. Схема каталога passage проектируется в этом документе: окончательный контракт каталога ещё нужно согласовать.

## 2. Общие соглашения

| Обозначение | Тип значения | Смысл |
|---|---|---|
| `enum` | Строка из согласованного списка | Машинный код переводится в русскую фразу по словарю |
| `string` | Строка | Текст без HTML; пробелы нормализуются |
| `array<enum>` | Массив кодов | Значения перечисляются понятными фразами без повторов |
| `null` | Неизвестное значение | Не равно отрицательному ответу; предложение о таком значении пропускается |

Длины текстов ниже — предлагаемые ограничения интерфейса для MVP, а не ограничения модели. Признаки с неизвестным статусом не превращаются в утверждения. Поле со статусом `INVALID` сначала обрабатывается валидацией, а не включается в текст как достоверное.

## 3. Query: поля формы пользователя

| Поле | Тип значения | Обязательность для MVP | Смысл и использование в query |
|---|---|---|---|
| `business.sector` | `enum` или `null` | Предусмотреть ответ «не знаю» | Фактическая отрасль. Код преобразуется в описание: «Бизнес занимается розничной торговлей». Не добавлять детализацию, которой нет в ответе |
| `request.purpose` | `enum` | Обязательно | Основная цель финансирования. Например, `WORKING_CAPITAL` → «Нужны средства для пополнения оборотного капитала» |
| `request.usageMode` | `enum` | Ответ обязателен, `UNKNOWN` допустим | Как пользователь планирует использовать деньги: разово, частями или как резерв. Новое предлагаемое поле |
| `request.description` | `string` или `null`, до 500 символов | Необязательно | Уточнение задачи словами пользователя. Новое предлагаемое поле. Дополняет контекст, не меняет структурированные ответы и правила |
| `security.collateralReady` | `enum`: `YES`, `NO`, `DISCUSS`, `UNKNOWN` | Предусмотреть `UNKNOWN` | Готовность обсуждать залог. Предлагаем заменить boolean. Не означает наличие проверенного обеспечения. В query использовать точную формулировку без домысливания предпочтений |
| `security.guarantorReady` | `enum`: `YES`, `NO`, `DISCUSS`, `UNKNOWN` | Предусмотреть `UNKNOWN` | Готовность привлечь поручителя. Предлагаем заменить boolean. Не подтверждает наличие или пригодность поручителя |

### 3.1. Предлагаемый словарь `request.usageMode`

| Значение | Тип | Смысл | Текст для query |
|---|---|---|---|
| `ONE_TIME` | `enum` | Нужна одна выдача | «Деньги нужны одной суммой» |
| `IN_PARTS` | `enum` | Деньги нужны постепенно | «Планируем использовать деньги частями по мере необходимости» |
| `ACCOUNT_RESERVE` | `enum` | Резерв на случай недостатка денег на счёте | «Нужен резерв средств на расчётном счёте на случай нехватки денег» |
| `UNKNOWN` | `enum` | Пользователь пока не определился | Предложение пропускается |

### 3.2. Примеры кодов отрасли и цели

| Поле | Значение | Русское представление |
|---|---|---|
| `business.sector` | `TRADE` | «торговля» |
| `business.sector` | `MANUFACTURING` | «производство» |
| `request.purpose` | `WORKING_CAPITAL` | «пополнение оборотных средств» |
| `request.purpose` | `CASH_GAP` | «покрытие кассового разрыва» |
| `request.purpose` | `EQUIPMENT` | «покупка оборудования» |
| `request.purpose` | `TRANSPORT` | «покупка транспорта» |
| `request.purpose` | `COMMERCIAL_PROPERTY` | «покупка коммерческой недвижимости» |
| `request.purpose` | `CONTRACT_EXECUTION` | «исполнение контракта» |
| `request.purpose` | `REFINANCING` | «рефинансирование действующих обязательств» |
| `request.purpose` | `DEVELOPMENT` | «развитие бизнеса или инвестиции» |

Это предлагаемые коды для согласования. Итоговый список отраслей и целей должен быть общим для формы, каталога и словарей FastAPI.

### 3.3. Шаблон query

```text
query: Бизнес занимается {sector_text}. Цель финансирования — {purpose_text}. {usage_sentence} {collateral_sentence} {guarantor_sentence} Дополнительные обстоятельства: {description}.
```

Шаблон собирается из отдельных непустых предложений, а не буквальной подстановкой всех полей. Если отрасль, описание или иной контекст неизвестны, соответствующая часть целиком отсутствует.

Пример:

```text
query: Бизнес занимается торговлей. Цель финансирования — пополнение оборотных средств. Планируем использовать деньги частями по мере необходимости. Не готовы предоставлять имущественный залог. Дополнительные обстоятельства: закупаем товар небольшими партиями перед сезоном.
```

Для `YES` по залогу: «Готовы обсудить предоставление имущественного залога». Для `DISCUSS`: «Возможность предоставления залога требует обсуждения». Не превращать эти ответы в «предпочитаем залоговый кредит».

## 4. Passage: поля кредитного продукта

Следующие поля — предлагаемый семантический слой каталога, а не замена тарифам и правилам применимости.

| Поле | Тип значения | Обязательность для MVP | Смысл и использование в passage |
|---|---|---|---|
| `product.id` | `string` | Обязательно | Стабильный идентификатор. В тексте не используется, связывает результат с продуктом |
| `product.version` | `string` | Обязательно | Версия карточки для актуальности эмбеддинга. В текст не включается |
| `product.name` | `string` | Обязательно в каталоге | Название для интерфейса. Рекламное название можно не включать в passage: оно не заменяет назначение продукта |
| `product.type` | `enum` | Обязательно | Механизм финансирования: разовый кредит, возобновляемая или невозобновляемая линия, овердрафт |
| `product.purposes` | `array<enum>` | Обязательно | Поддерживаемые цели. Используется тот же словарь, что у `request.purpose` |
| `product.usageModes` | `array<enum>` | Обязательно | Поддерживаемые способы использования. Используется тот же смысловой словарь, что у `request.usageMode`, без `UNKNOWN` |
| `product.targetScenario` | `string`, до 500 символов | Обязательно | Проверенное описание ситуации применения: «для повторяющихся закупок товаров». Заполняется авторами каталога, не выдумывается при запросе |
| `product.targetSectors` | `array<enum>` | Необязательно; пустой массив — без специализации | Отрасли, на которые продукт специально ориентирован. Не путать с разрешёнными или исключёнными отраслями в правилах |
| `product.specialization` | `string` или `null`, до 200 символов | Необязательно | Специализация, которой недостаточно отраслевого кода: например, продавцы маркетплейсов. При отсутствии пропускается |
| `product.collateralRequirement` | `enum`: `NONE`, `REQUIRED`, `CONDITIONAL` | Обязательно | Требование к имущественному залогу. Должно соответствовать правилам каталога |
| `product.guarantorRequirement` | `enum`: `NONE`, `REQUIRED`, `CONDITIONAL` | Обязательно | Требование к поручителю. Не смешивать с имущественным залогом |
| `product.securityNote` | `string` или `null`, до 200 символов | Обязательно при `CONDITIONAL` в любом требовании | Уточнение, когда и какое обеспечение требуется. При неизвестных правилах не заявлять отсутствие требования |

### 4.1. Предлагаемый словарь `product.type`

| Значение | Тип | Русское представление |
|---|---|---|
| `TERM_LOAN` | `enum` | «кредит с разовой выдачей» |
| `REVOLVING_CREDIT_LINE` | `enum` | «возобновляемая кредитная линия» |
| `NON_REVOLVING_CREDIT_LINE` | `enum` | «невозобновляемая кредитная линия» |
| `OVERDRAFT` | `enum` | «овердрафт по расчётному счёту» |

### 4.2. Шаблон passage

```text
passage: Тип финансирования — {type_text}. Назначение — {purposes_text}. {usage_sentence} Сценарий применения: {targetScenario}. {sector_sentence} {specialization_sentence} {collateral_sentence} {guarantor_sentence} {securityNote}.
```

Пример:

```text
passage: Тип финансирования — возобновляемая кредитная линия. Назначение — пополнение оборотных средств и закупка товаров. Средства используются частями в пределах лимита. Сценарий применения: регулярные закупки по мере необходимости. Имущественный залог не требуется. Поручительство требуется.
```

Включать только подтверждённые свойства. Если продукт не имеет отраслевой специализации, не приписывать ему отрасль ради сходства с запросом.

## 5. Какие поля не включаем в семантический текст MVP

Поля продолжают передаваться структурированно, если нужны Spring Boot. Они не теряются, но не используются как способ поручить E5 числовую проверку.

| Поля | Тип значения | Смысл и обработка |
|---|---|---|
| Сумма запроса и диапазоны сумм продукта | `money` | Проверка диапазона в Spring Boot. Для линии отдельно определён смысл суммы как лимита |
| Срок запроса и диапазоны сроков | `integer`, месяцы | Проверка в Spring Boot; срок лимита не смешивается со сроком транша |
| Выручка и период | `money` + даты | Расчёт показателя и проверка требований на бэкенде |
| Дата регистрации и фактического начала работы | `date` | Расчёт стажа и проверка соответствующего требования |
| Возраст предпринимателя | `integer` | Только соответствующие правила; не путать со стажем ИП |
| Реестр МСП, категория, налоговый режим | Статусы и `enum` | Проверки условий продукта |
| Страна и регион | Коды территории | Географические ограничения |
| Стаж счёта и продаж на маркетплейсе | `integer`, месяцы | Проверки специальных условий. Смысловая специализация маркетплейса при необходимости описывается отдельно |
| Ставка и комиссии | Числа и структурированные тарифы | Отображение и отдельные расчёты. Их наличие в тексте не гарантирует правильного сравнения стоимости моделью |
| `ELIGIBLE`, `CONDITIONAL`, `INELIGIBLE` | `enum` | Применимость определяет Spring Boot. `INELIGIBLE` исключаются из рекомендаций; предупреждения `CONDITIONAL` сохраняются отдельно |

## 6. Порядок работы

1. Согласовать каталог и словари кодов.
2. Составить passage для каждого продукта из подтверждённых значений.
3. Рассчитать нормализованные эмбеддинги и сохранить связь `product.id` + `product.version` + версия модели и шаблона.
4. При подборе Spring Boot передаёт профиль и допустимые продукты.
5. FastAPI собирает query, рассчитывает его эмбеддинг и сравнивает только с допустимыми продуктами.
6. Возвращает идентификаторы, порядок и техническую оценку сходства; предупреждения применимости не теряются.
7. При изменении семантических полей продукта пересчитать его passage и эмбеддинг. При смене модели или шаблона passage пересчитать каталог.

Оценка сходства — не вероятность одобрения и не готовый процент финансовой пригодности. Шаблоны и качество ранжирования проверяются на вручную размеченных примерах. Собственное дообучение для первой версии не предусматривается.
