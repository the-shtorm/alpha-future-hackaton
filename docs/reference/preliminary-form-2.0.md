# Предварительная форма подбора кредитов (Preliminary Form)

Версия 2.0 (Синхронизирована с `query_passage_mvp.md` и `data-policy.md`). Документ описывает поля предварительной формы — входные данные для жесткой фильтрации в Spring Boot и семантического ранжирования в FastAPI (`intfloat/multilingual-e5-small`). Из формы исключены избыточные географические, дублирующие и неиспользуемые моделями поля.

## 1. Назначение и границы

Предварительная форма заполняется клиентом до подачи кредитной заявки. Обработка делится на два этапа:

1. **Жесткая фильтрация (Spring Boot):** Сопоставляет параметры бизнеса и запроса с правилами каталога продуктов и присваивает каждому продукту статус применимости (`ELIGIBLE`, `CONDITIONAL`, `INELIGIBLE`). Продукты со статусом `INELIGIBLE` отсеиваются.
2. **Семантическое ранжирование (FastAPI):** Из текстовых и категориальных полей анкеты собирается поисковый запрос (`query`), который сравнивается по косинусной близости с описаниями (`passage`) допустимых продуктов.

Рейтинг рекомендации отражает смысловое соответствие продукта потребности клиента и не является вероятностью одобрения кредита.

## 2. Словарь полей предварительной формы

В предварительной форме используется **14 полей** (вместо прежних 18: удалены дублирующая дата регистрации `registeredOn`, география `country`/`region` и узкоспециализированные счетчики, не влияющие на модели).

### 2.1. Профиль бизнеса и налоги

* `registration.borrowerKind` (`enum`: `IP`, `LLC`): Организационно-правовая форма заемщика (ИП или ООО). Обязательно.
* `business.sector` (`enum` или `null`): Отрасль фактической деятельности (`TRADE`, `MANUFACTURING`, `SERVICES`, `IT`, `CONSTRUCTION`, `AGRICULTURE`, `LOGISTICS`). Допускается `null` («не знаю») на этапе подбора.
* `business.actualStartedOn` (`date`, `YYYY-MM-DD`): Дата фактического начала ведения бизнеса. Используется как единая точка отсчета стажа бизнеса.
* `business.taxRegime` (`enum`: `OSNO`, `USN`, `PSN`, `AUSN`, `NPD`, `UNKNOWN`): Налоговый режим.
* `business.mspRegistry` (`boolean` или `null`): Нахождение компании в едином реестре субъектов МСП.

### 2.2. Оборот бизнеса

* `financial.revenue` (`money`, десятичная строка в `RUB`, например `"24000000.00"`): Общая выручка (оборот) за указанный период.
* `financial.periodFrom` (`date`, `YYYY-MM-DD`): Начало периода расчета выручки (1-е число месяца).
* `financial.periodTo` (`date`, `YYYY-MM-DD`): Конец периода расчета выручки (последний день месяца, не позже текущей даты UTC).

### 2.3. Параметры кредитного запроса

* `request.purpose` (`enum`): Основная цель финансирования (`WORKING_CAPITAL`, `CASH_GAP`, `EQUIPMENT`, `TRANSPORT`, `COMMERCIAL_PROPERTY`, `CONTRACT_EXECUTION`, `REFINANCING`, `DEVELOPMENT`). Обязательно.
* `request.amount` (`money`, десятичная строка в `RUB`): Желаемая сумма кредита или лимита ($> 0$). Обязательно.
* `request.termMonths` (`integer`): Желаемый срок кредита в полных месяцах ($1 \dots 360$). Обязательно.
* `request.usageMode` (`enum`: `ONE_TIME`, `IN_PARTS`, `ACCOUNT_RESERVE`, `UNKNOWN`): Предполагаемый режим использования заемных средств (разово всей суммой, частями по мере необходимости или как резерв на счете). Обязательно (допустим ответ `UNKNOWN`).
* `request.description` (`string` или `null`, до 500 символов): Свободное описание бизнес-задачи словами пользователя для уточнения контекста в модели эмбеддингов. Необязательно.

### 2.4. Намерения по обеспечению

Для согласованности с семантическим ранжированием используются перечисления вместо булевых флагов:

* `security.collateralReady` (`enum`: `YES`, `NO`, `DISCUSS`, `UNKNOWN`): Готовность предоставить имущественный залог.
* `security.guarantorReady` (`enum`: `YES`, `NO`, `DISCUSS`, `UNKNOWN`): Готовность привлечь поручителя.

## 3. Использование полей в контуре подбора

| Поле | Проверка в Spring Boot (Правила каталога) | Участие в `query` для FastAPI (E5) |
| --- | --- | --- |
| `request.purpose` | Входит в массив `product.purposes` | Да (текст цели финансирования) |
| `request.amount` | В диапазоне $[\text{minAmount}, \text{maxAmount}]$ | Нет (числовая проверка на бэкенде) |
| `request.termMonths` | В диапазоне $[\text{minTermMonths}, \text{maxTermMonths}]$ | Нет (числовая проверка на бэкенде) |
| `request.usageMode` | Совместимость с `product.usageModes` (при `UNKNOWN` — пропуск проверки) | Да (предложение о режиме использования средств) |
| `request.description` | Валидация длины ($\le 500$ символов) и отсутствия HTML | Да (блок «Дополнительные обстоятельства») |
| `registration.borrowerKind` | Входит в `product.borrowerKinds` (`IP` / `LLC`) | Нет |
| `business.sector` | Не входит в `excluded_sectors` каталога | Да (фраза о сфере деятельности бизнеса) |
| `business.actualStartedOn` | Полных месяцев стажа $\ge$ `min_business_age_months` | Нет |
| `business.taxRegime` | Входит в `eligibility.tax_regimes` (для `LLC` запрещены `PSN` и `NPD`) | Нет |
| `business.mspRegistry` | Проверка `true`, если продукт требует статус МСП | Нет |
| `financial.revenue`, `periodFrom`, `periodTo` | Среднемесячная выручка $\ge$ `min_average_monthly_revenue_rub` | Нет |
| `security.collateralReady` | Сравнение с `product.collateralRequirement` (`NONE`, `REQUIRED`, `CONDITIONAL`) | Да (отношение к имущественному залогу) |
| `security.guarantorReady` | Сравнение с `product.guarantorRequirement` (`NONE`, `REQUIRED`, `CONDITIONAL`) | Да (отношение к поручительству) |

### Правило сопоставления обеспечения на этапе подбора:
* Если у продукта требование `REQUIRED`, а клиент указал `NO` $\to$ статус продукта `INELIGIBLE`.
* Если у продукта требование `REQUIRED` или `CONDITIONAL`, а клиент указал `DISCUSS` или `UNKNOWN` $\to$ статус продукта `CONDITIONAL` (с предупреждением о необходимости подтвердить обеспечение на этапе заявки).
* Если у продукта `NONE` или клиент указал `YES` $\to$ проверка пройдена (`MATCH`).

## 4. Нормализация и передача данных в заявку

* Все правила типов (`money`, `date`, `enum`) и статусов качества (`value_status`: `KNOWN`, `UNKNOWN`, `INVALID`) едины с документом `data-policy.md`.
* После выбора клиентом конкретного продукта из ранжированного списка создается черновик кредитной заявки (`Application`).
* В окончательную заявку автоматически переносятся **12 структурированных полей** из предварительной формы (все поля, кроме чисто семантических `request.usageMode` и `request.description`, которые выполнили свою роль на этапе ранжирования).
