# Кредитный скоринг и банковское решение

[Навигация](README.md) · [Запуск](hackathon-start.md) · [Модель из HF](../fastapi/SCORING_HF.md)

## Рабочая модель

FastAPI выполняет CPU inference CatBoost `sba-scoring-v2`, обученного на данных SBA.
Java подготавливает признаки и применяет финансовую политику
`data-policy-3.0-sba-annuity-1`. На этапе подбора отдельно работает дообученный E5.
Обе модели загружаются при запуске сервиса и используются повторно.

| Идентификатор | Значение |
|---|---|
| HTTP-схема | `sba-scoring-1` |
| Признаки | `sba-features-1` |
| Модель | `sba-scoring-v2` |
| Выбранный кандидат | `mixed-v1-0051` |
| Калибровка | `sba-scoring-v2-sigmoid-fy2012` |
| Operating threshold пакета | `0.167204479067272` |
| HF revision | `5a0049417dae97bdc8a341c89c705d7505563645` |

Штатная настройка: `SCORING_ENABLED=true`, `SCORING_MODEL_PATH=thedauns/sba-scoring-v2`.
Короткое имя разрешается через lock-файл в immutable HF revision. Загрузчик проверяет
manifest, SHA-256 файлов, версии и контрольный прогноз native CatBoost. Файлы модели
хранятся в Docker volume `recsys_model_cache`. Локальный экспорт поддерживается через
`/scoring-models/<каталог>`; команды проверки и подготовки описаны в
[SCORING_HF.md](../fastapi/SCORING_HF.md). API доступен во внутренней Docker-сети.

## Признаки и HTTP

Java отправляет `POST /api/v1/scoring/evaluate` с внутренним ключом `RECSYS_API_KEY`.
Вход включает `schemaVersion=sba-scoring-1`, `requestId` и девять признаков:

| Поле | Смысл |
|---|---|
| `loanAmountUsd` | Сумма в USD; адаптер демонстрационной политики использует 90 RUB/USD |
| `termMonths` | Срок в месяцах |
| `initialInterestRatePct` | Годовая ставка в процентных пунктах |
| `interestRateType` | Тип ставки |
| `isRevolving` | Возобновляемый механизм кредита |
| `hasCollateral` | Наличие обеспечения по условиям кандидата |
| `businessType` | Тип заёмщика из IP/LLC |
| `businessAgeCategory` | Возрастная категория бизнеса |
| `naicsCode` | Код отрасли из фиксированного соответствия sector → NAICS |

Проверенные схемы и mappings находятся в `fastapi/app/scoring/` и
`fastapi/config/`. Ответ сохраняет вероятность списания SBA, score,
model/feature/calibration versions. Operating threshold доступен через
`GET /api/v1/scoring/model-info` и проверку пакета. Контрактные JSON
публикуются в [docs/contracts](contracts/README.md).

## Политика решения

1. Проверить текущую ревизию, документы, выручку, ограничения продукта и макроконтекст.
2. При `overdue > 0.20` применить жёсткий отказ до вызова модели.
3. Рассчитать среднемесячную выручку, бюджет платежа и аннуитет с обслуживанием.
   Неположительный бюджет нового платежа даёт отказ.
4. Получить `p_sba`; рассчитать `p_final = min(1, p_sba + 0.50 × overdue)`.
5. При `p_final <= 0.15` и `PTI <= 0.40`, с выполненными условиями продукта,
   сформировать `APPROVED`. При исходном `p_final > 0.35` сформировать отказ.
6. Для промежуточного риска или превышения нагрузки рассчитать одну альтернативу
   в пределах правил продукта. Ставка: максимум базовой ставки и
   `keyRatePct + 5 + 20 × исходный риск`, пять знаков `HALF_UP`.
   Допустимая сумма определяется по бюджету платежа. Увеличение срока на 12 месяцев
   применяется при перегрузке, если продукт разрешает `TERM_INCREASE`.
7. Оценить альтернативу той же моделью и калибровкой. При риске `<= 0.35` и
   `PTI <= 0.40` сохранить `COUNTEROFFERED`, условия и SHA-256.

Выполняются максимум два ML-вызова: исходный и один альтернативный кандидат.
Недостающие значения и подтверждения возвращаются клиенту как `REQUEST_INFO`;
проверки для сотрудника банка отображаются в истории рассмотрения. Порог
operating threshold из пакета относится к оценке модели; правила банковского
решения используют отдельно заданные выше уровни риска.

## Сохранение и акцепт

В `assessment_run` хранятся вход, выход, вероятность, версия и evidence.
`credit_decision` ссылается на выбранную оценку и поданную ревизию. API journey
показывает `conditions`, `scoringAssessments`, `assessmentIds`, выбранный вариант,
PTI и основания. Макроконтекст имеет свой источник и срок действия; создать его
может BANK_APPROVER через UI либо `POST /bank/macroeconomic-contexts`.

Для `APPROVED` создаётся Offer, клиент вызывает `offers/accept`. Для
`COUNTEROFFERED` клиент передаёт `proposalId`, `termsSha256`, `confirmed=true`
в `counteroffers/accept`; Offer создаётся и принимается атомарно. Затем клиент
подписывает демонстрационный договор, банк подтверждает выдачу. Инструкция с
конкретными данными: [сценарий проверяющего](hackathon-start.md).

## Обучение и происхождение

SBA-модель оценивает историческую цель списания SBA. В приложении она используется
в демонстрационной политике для синтетических кредитных продуктов. На сохранённой
когорте FY2023 выбранный пакет имеет recall 70.08%, precision 58.96%, F1 64.04%
при закреплённом пороге. Это результат сохранённого эксперимента; состав когорт,
метрики и воспроизводимость приведены в [материалах обучения](../fastapi/scoring_training/README.md)
и [индексе экспериментов](../fastapi/experiments/README.md).
