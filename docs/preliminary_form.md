# Предварительная форма подбора

Текущая версия — **`preliminary-2.0`**, 15 отдельных полей. Полный словарь типов, enum и правил — [контракт полей](backend-fields-v3.md). [Пример JSON](contracts/preliminary-2.0.example.json).

## Содержание

| Группа | Поля |
|---|---|
| Бизнес | Форма ИП/ООО, отрасль, фактическое начало деятельности, налоговый режим, реестр МСП |
| Финансы | Выручка, начало и конец её периода |
| Запрос | Цель, сумма, срок, режим использования, описание |
| Обеспечение | Готовность к залогу и поручительству |

Выручка указывается за период целиком. Для подбора при известной выручке выбираются полные календарные месяцы: первое число первого месяца и последнее число последнего месяца.

## Работа формы

1. Клиент заполняет форму и сохраняет черновик.
2. После входа форма привязывается к доступной организации.
3. Сервер проверяет применимость продуктов и вызывает E5.
4. Клиент просматривает условия и выбирает версию продукта.
5. Создаётся заявка с 13 перенесёнными общими полями.

Два поля — `request.usageMode` и `request.description` — используются в контексте подбора. Четыре дополнительных поля окончательной заявки вводятся на следующем этапе.

## Представление значений

Money передаётся строкой с двумя знаками после точки; срок — целым JSON-числом, реестр МСП — boolean. `null`, отсутствие и `UNKNOWN` сохраняют смысл неизвестного значения. `0.00` и `false` означают известные значения.

Поля `business.sector`, `request.purpose`, `request.usageMode`, `request.description`, `security.collateralReady`, `security.guarantorReady` формируют семантический query. Применимость по сумме, сроку и финансовым параметрам проверяет Java.

## API

- `GET /forms/preliminary` — схема.
- `GET /forms/preliminary/dictionaries` — словари.
- `POST /selection-profiles` — создание.
- `PATCH /selection-profiles/{id}` — сохранение с expectedVersion.
- `POST /selection-profiles/{id}/automatic-selection` — подбор.
- `PUT /selection-profiles/{id}/selected-product` — выбор по runId и версии.
