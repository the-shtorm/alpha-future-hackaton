# Предварительная форма подбора кредитов (Preliminary Form)

Версия 1.0. Документ описывает поля предварительной формы — входные данные рекомендательного алгоритма, который подбирает клиенту подходящие кредитные предложения. Это пара к `data_policy (1).md`: здесь — только подбор (рекомендации), там — поля окончательной заявки и ML-скоринг.

## 1. Назначение и границы

Предварительная форма заполняется на сайте до подачи заявки. По ее полям рекомендательный алгоритм сопоставляет профиль бизнеса и запрос с условиями каталога кредитных продуктов и выдает список подходящих предложений.

* Основание рекомендации: тип бизнеса, отрасль, размер, стаж, оборот и параметры запроса (сумма, срок, цель).

* По этим данным клиент выбирает понравившееся предложение и переходит к окончательной заявке.

* Скоринг и проверка валидности кредитной заявки здесь не выполняются: ими занимается алгоритм скоринга по полям из `data_policy (1).md`.

## 2. Словарь полей

### 2.1. Тип, отрасль и размер бизнеса

* `registration.borrowerKind` (enum): Тип бизнеса: ИП (`IP`) или ООО (`LLC`).

* `business.sector` (enum): Отрасль фактической деятельности (напр., `TRADE`, `MANUFACTURING`).

* `business.mspRegistry` (boolean): Размер бизнеса — сведения о категории субъекта МСП.

### 2.2. Стаж и налогообложение

* `registration.registeredOn` (date): Дата государственной регистрации (возраст бизнеса).

* `business.actualStartedOn` (date): Дата фактического начала деятельности (фактический стаж).

* `business.taxRegime` (enum): Налоговый режим (напр., `USN`, `OSNO`, `PSN`).

### 2.3. Оборот

* `financial.revenue` (money): Выручка (оборот) за выбранный период.

* `financial.periodFrom` / `financial.periodTo` (date): Границы периода оборота.

### 2.4. Параметры запроса

* `request.purpose` (enum): Цель финансирования (напр., `WORKING_CAPITAL`); сопоставляется с назначением продукта.

* `request.amount` (money): Желаемая сумма кредита; сопоставляется с допустимым диапазоном продукта.

* `request.termMonths` (integer): Срок в месяцах; сопоставляется с допустимым диапазоном продукта.

### 2.5. Условные поля (для отдельных правил подбора)

* `registration.country` (enum): Страна регистрации (напр., `RU`).

* `business.region` (string): Регион фактической работы бизнеса.

* `business.ipAgeYears` (integer): Возраст ИП в полных годах (только для `IP`).

* `security.collateralReady` (boolean): Готовность обсудить имущественный залог (для продуктов с залогом).

* `security.guarantorReady` (boolean): Готовность привлечь поручителя (для продуктов с поручительством).

* `business.marketplaceMonths` (integer): Длительность продаж на маркетплейсе, мес. (для соответствующих продуктов).

* `business.bankAccountMonths` (integer): Стаж счета в банке, мес. (для продуктов с условием счета/оборотов).

## 3. Как поля используются рекомендательным алгоритмом

| Поле | Правило подбора |
| ----- | ----- |
| `request.purpose` | Назначение продукта включает цель |
| `request.amount` | Сумма в диапазоне `minAmount`…`maxAmount` продукта |
| `request.termMonths` | Срок в диапазоне `minTermMonths`…`maxTermMonths` продукта |
| `registration.borrowerKind` | Продукт допускает форму заемщика (`IP`/`LLC`) |
| `registration.registeredOn`, `business.actualStartedOn` | Минимальный возраст бизнеса (`min_business_age_months`) |
| `business.sector` | Отрасль не входит в исключения продукта (`excluded_sectors`) |
| `business.taxRegime` | Режим входит в допустимые (`tax_regimes`) |
| `financial.revenue`, `financial.periodFrom` / `periodTo` | Среднемесячный оборот ≥ `min_average_monthly_revenue_rub`; окно ≈ `revenue_window_months` |
| `business.mspRegistry` | Условие членства в реестре МСП, когда оно требуется |
| `business.ipAgeYears` | Минимальный возраст ИП (`min_ip_age_years`) |
| `security.collateralReady`, `security.guarantorReady` | Продукт с залогом/поручительством предлагается только при готовности их обсудить |
| `business.marketplaceMonths`, `business.bankAccountMonths` | Дополнительные условия отдельных продуктов |
| `registration.country`, `business.region` | Географические ограничения продукта |

Порядок рекомендаций строится по применимости, параметрам запроса и предпочтениям. Рейтинг рекомендации не является вероятностью одобрения.

## 4. Нормализация и качество данных

* Типы (`money`, `date`, `boolean`, `enum`), правила нормализации и мета-статус `value_status` (`KNOWN` / `UNKNOWN` / `INVALID`) — общие с `data_policy (1).md`, раздел 1.

* Производные значения подбора считает система: среднемесячный оборот = `revenue` / число полных месяцев периода; возраст бизнеса = полные месяцы от даты до даты расчета.

* Неизвестное значение не равно нулю. Если поле не заполнено или «клиент не знает», условие продукта не считается выполненным: продукт может быть показан как условный (`CONDITIONAL`) с пометкой «потребуется подтвердить».

## 5. Результат подбора

* Ранжированный список кредитных предложений с объяснением: выполненные условия, нарушения и неподтвержденные сведения. Статусы применимости: `ELIGIBLE` / `CONDITIONAL` / `INELIGIBLE`.

* Рекомендация не является кредитным решением. После выбора предложения данные формы переносятся в окончательную заявку (см. `data_policy (1).md`), где алгоритм скоринга рассчитывает валидность кредитной заявки.
