# Task reports

For every task, regardless of its area (backend, frontend, database, infrastructure,
documentation, research, or other work), create a NEW report under `docs/agents/` with
an individual, descriptive filename such as `YYYY-MM-DD-task-name.md`. If that name
already exists, add a unique descriptive suffix. Do not append a new task report to
an existing task's log and do not overwrite completed reports. Maintain the current
task's own report as work progresses and finalize it when the task ends.

`docs/agents/log.md` is the shared index linking to individual reports, not a combined
log. Preserve historical reports and area-specific indexes such as
`docs/agents/backend/log.md`; new tasks use the shared reporting workflow above.

Record the request and constraints, changes and affected files or artifacts, contract
and migration impacts where applicable, commands and actual verification results,
limitations, and Git status where relevant. Distinguish working behavior, demo
placeholders, and planned work. Do not include secrets, tokens, or personal data,
and do not claim checks that were not run. For non-code tasks, record the sources
and resulting deliverables instead of inventing test or Git results.

This reporting workflow applies to ALL tasks and was requested and clarified
explicitly by the user.
