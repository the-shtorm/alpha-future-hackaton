# Backend task reports

For every backend task, create a NEW report under `docs/agents/backend/` with a unique,
descriptive filename (for example `YYYY-MM-DD-task-name.md`). Do not append a new task
report to an existing task's log and do not overwrite earlier task reports. For the current
task, maintain its own report as work progresses and finalize it when the task ends.
`docs/agents/backend/log.md` is an index linking to individual reports, not a combined log.

Record the request and constraints, changes and affected files, API/migration impacts,
commands and actual verification results, limitations and Git status. Distinguish working
behavior, demo placeholders, and planned work. Do not include secrets, tokens or personal
data, and do not claim checks that were not run. This reporting workflow was requested
and clarified explicitly by the user.
